Musgenpro explores a structured, controllable workflow for analyzing an existing musical fragment, transforming selected musical properties, and returning a new generative interpretation directly to the production timeline.

01 · Concept

From audio clip to musical blueprint.

Instead of treating generative music as a separate website, Musgenpro investigates a DAW-native workflow: select a clip, analyze it deeply, decide what should remain and what may change, then generate a new interpretation.

02 · Analysis

More than a text prompt.

The source fragment is analyzed as music, audio and production. Measurable values are handled locally; semantic and perceptual properties are handled by multimodal models.

Musical structure

  • Tempo, meter, beats and bars
  • Key and harmonic movement
  • Chord progression and timing
  • Melodic information
  • Sections, phrases and transitions

Sound & production

  • Instrumentation and musical roles
  • Register and tessitura
  • Timbre and sound design
  • Rhythm, groove and density
  • Mix, stereo image, spatial processing and effects

Vocals

  • Lyrics and language
  • Vocal melody and register
  • Delivery, articulation and timbre
  • Backing vocals and doubles
  • Pitch, formant and spatial processing
03 · Blueprint

A structured representation.

The analysis is fused into a machine-readable Musical Blueprint. This allows downstream generation to be driven by explicit musical properties rather than an unstructured description alone. 

{
  "tempo": 128.0,
  "meter": "4/4",
  "key": "F# minor",
  "harmony": {
    "chords": "...",
    "timing": "..."
  },
  "structure": "...",
  "melody": "...",
  "instrumentation": "...",
  "timbre": "...",
  "production": "...",
  "vocals": "...",
  "energy_curve": "..."
}

Separate what the music is from how it should be transformed.

The source analysis remains immutable. A second target blueprint is created from the user's preservation controls, allowing the original musical description and the desired transformation to remain clearly separated.

This makes the workflow suitable for experimentation with both cloud and local generation backends.

05 · Research stack

Hybrid by design.

06 · DAW integration

REAPER first. DAW-agnostic core.

The first implementation targets REAPER. The analysis and generation backend is intentionally separated from the DAW-specific control layer, making future adapters for other professional audio workstations possible.
